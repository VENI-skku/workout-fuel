# 운동별 간편식 추천 서비스 (Workout Fuel) — 기술 상세

> 이어받는 사람은 먼저 **HANDOFF.md**를 읽으세요. 이 문서는 세팅·KPI·버전 기록 등 상세 참고용입니다.

운동 종류·시간·체중을 입력하면 소모 칼로리를 계산하고, 회복에 맞는
단백질·탄수화물 목표량을 잡아 쿠팡 간편식 검색으로 연결해 주는 서비스.

- **가설:** 운동 후 "뭘 먹지"를 고민하는 사람에게 소모 칼로리 기반 간편식을 바로 추천하면, 식단 결정 시간을 줄이고 실제 구매 행동까지 이어질 것이다.
- **타겟:** 헬스·러닝 등 운동 후 간편식으로 끼니를 챙기는 사람
- **AS-IS → TO-BE:** 직접 검색하며 고민 → 소모량 맞춤 추천으로 원클릭 이동

## MVP 버전 기록 (발전 과정 = 채점 핵심)
버전 올릴 때마다 여기 기록. 발표 때 "1.0 → 2.0"의 변화가 곧 스토리.

### MVP 1.0 (초기 배포)
- 날짜: 2026-08-17
- 배포 URL: https://skku137ai.netlify.app/
- 핵심 기능: 칼로리 계산 + 3개 카테고리 추천 카드 + 쿠팡 연결
- 측정 시작 KPI: 아래 표 참고

### MVP 2.0 (1차 피드백 반영)
- 날짜: 2026-08-19
- 바뀐 점
  1. 페이지 명을 “칼로리 연소 계산기”에서 “소모 칼로리 맞춤 식단”으로 변경
  2. 추천 카드 버튼을 쿠팡 단일 연결에서 “대용량 쟁여두기용”과 “맞춤 한끼용”으로 분리
  3. 추천 카드 설명을 광고형 문구에서 식단 선택형 문구로 개선
  4. GA4 이벤트에 mvp_version 파라미터를 추가해 1.0/2.0 비교 가능하게 구성
- 바꾼 이유(어떤 피드백/데이터 때문에)
  1. 유저 테스트에서 “쿠팡 광고처럼 느껴져 클릭하지 않았다”는 반응이 반복적으로 확인됨
  2. 사용자는 소모 칼로리 계산보다는 “오늘 운동 후 무엇을 먹을지”를 더 궁금해했으므로 서비스 정체성을 식단 추천으로 정리함
  3. 쇼핑몰 단일 연결 구조가 대량 구매 부담을 만들었기 때문에, 대용량 구매형/소량 구매형 선택지를 분리함
- 지표 변화(1.0 대비)
  1. 초기 MVP 1.0은 추천 클릭 0건, 전환율 0.0%
  2. MVP 2.0 목표는 광고성 거부감을 줄여서 추천 클릭률을 15% 이상으로 개선하는 것을 목표로 설정
  3. 

### 배포 중 겪은 문제 & 해결 (숨기지 말 것 — 고득점 포인트)
1. 문제: Netlify 팀 프로젝트 접근이 막혀 있어, GitHub 저장소는 초대됐지만 실제 Netlify 프로젝트 배포 권한은 확보되지 않았음
- 원인: Netlify 팀 플랜/권한 조건이 충족되지 않았고, GitHub 초대와 Netlify 배포 권한이 별개였음
- 해결: GA4와 코드 반영은 진행하고, 배포는 개인 계정 또는 권한 확보 후 다시 연결하는 흐름으로 정리
- 추가 개선: 배포 전 “팀 권한 확인 체크리스트”를 만들고, 브랜치/배포 계정 관리 기준을 사전에 정리해 불필요한 진단 시간을 줄일 것

## KPI 정의 (승주 데이터 분석용)

| 지표 | 정의 | 어디서 보나 |
|---|---|---|
| 방문자 수 | 페이지 순 사용자 | GA4 기본 `page_view` |
| 추천 클릭(전환) | 쿠팡 카드를 실제로 누른 횟수 | GA4 이벤트 `recommend_click` |
| 전환율 | 추천 클릭 ÷ 방문자 | GA4에서 계산 |
| 인기 운동/티어 | 클릭 시 함께 기록되는 `exercise`·`tier` | `recommend_click` 파라미터 |
| 버전별 비교 | MVP 1.0 vs 2.0 지표 | `recommend_click`의 `mvp_version` 파라미터 |
| 막히는 지점 | 이탈·헤매는 구간 (정성) | Clarity 세션 녹화·히트맵(선택) |

> `recommend_click`이 핵심 전환 이벤트다. "추천까지 도달해서 실제로 눌렀는가"가
> 성공을 가르는 KPI이므로 발표의 중심 숫자로 둘 것.
> 세부 파라미터(exercise·tier 등)를 표준 보고서에서 쪼개 보려면 GA4에서
> "맞춤 측정기준" 등록이 한 번 필요함(이벤트 발생 횟수 자체는 등록 없이도 바로 보임).

## 세팅 순서

### 1) 구글 애널리틱스 GA4 (필수)
1. https://analytics.google.com → 계정/속성 생성
2. "웹" 데이터 스트림 추가 → 배포 URL 입력
3. 발급된 **측정 ID**(`G-`로 시작) 복사
4. `index.html` 상단 GA4 스크립트의 측정 ID **두 군데** 교체
5. 배포 후 GA4 "실시간" 보고서에서 접속 잡히는지 확인
6. `recommend_click`은 며칠 뒤 "이벤트" 보고서에 표시(원하면 "주요 이벤트"로 지정)

### 2) Microsoft Clarity (선택)
1. https://clarity.microsoft.com → 프로젝트 생성
2. 프로젝트 ID를 `index.html`의 `YOUR_CLARITY_ID`에 교체
3. 안 쓸 거면 해당 스크립트 블록을 통째로 삭제

### 3) 배포 (Netlify)
- 간단: https://app.netlify.com/drop 에 폴더 드래그 → URL 즉시 생성
- 권장(Git 연동): GitHub repo 연결 → 커밋마다 자동 재배포 + 커밋 히스토리가 1.0→2.0 발전 증거
